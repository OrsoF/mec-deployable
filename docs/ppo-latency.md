# PPO decision latency

The README reports a local measurement of **the complete static PPO decision path**, without comparing solving methods. The numerical source is [ppo_latency_smoke.json](ppo_latency_smoke.json), generated by [measure_ppo_latency.py](../scripts/measure_ppo_latency.py) on 14 October 2026.

| Measurement | Recorded value |
| --- | ---: |
| Median (p50) validated decision | 42.61 ms |
| p95 validated decision | 59.37 ms |
| Initial engine construction | 6,086.43 ms |
| Warmups / measured requests | 5 / 100 |
| PPO edits per request | 96 |

The timer surrounds `DecisionEngine.decide` from the outside with `perf_counter_ns`. The model is loaded once and reused. Each request includes seed/path/environment construction, observation-normalization loading, one deterministic PPO edit episode, feasibility checks and construction of the output dictionary. It excludes input parsing, initial checkpoint loading, JSON serialization, disk writes and HTTP transport. Initial engine construction is recorded separately and includes lazy imports of the RL libraries; it is not a pure weight-loading timer.

The instance is [routing_bottleneck_heldout](../instances/eval/bottleneck_unseen.json): six nodes, seven physical links, two services and four demands. CPU execution used Python 3.12.14, PyTorch 2.14.1+cpu, SB3 2.9.0 and 14 PyTorch threads on Windows. Processor identification, logical CPU count, dependency versions, checkpoint/instance SHA-256 hashes and all 100 raw samples are recorded in the JSON.

## Interpretation

The available trusted checkpoint was trained for **512 steps**, as part of the earlier [CI smoke verification](ci-verification.md). It is not bundled in Git. It served **4 of 28 requested Mbps** in these deterministic requests. This checkpoint verifies the execution pipeline; it does not establish useful placement quality. Latency depends on the policy's actions, especially whether they trigger rerouting-and-uplift operations, so timings from this smoke policy are not representative of a well-trained policy by default.

These are repeated serial requests on one synthetic case. They do not measure concurrent API load, new topologies, production network conditions, or a distribution of independent tasks. p95 is the 95th percentile of the request timings using NumPy's default linear interpolation, not a confidence bound. No wall-time cutoff is enforced for static PPO.

## Reproduce

After following the README training commands, time your own trusted checkpoint:

```bash
python scripts/measure_ppo_latency.py --checkpoint outputs/ppo_bottleneck --warmup 5 --repeats 100 --output outputs/ppo_latency.json
```

To repeat the recorded run, use the existing local smoke artifact if available:

```bash
python scripts/measure_ppo_latency.py --checkpoint outputs/ci-verification/ppo_smoke --output outputs/ppo_latency_smoke_repeat.json
```

The earlier checkpoint may be absent in a fresh checkout. Its hashes in the result identify the exact artifact used; generating another smoke checkpoint is a different artifact and experiment. The checkpoint format is pickle-based, so only use files from a trusted source. Reruns write to ignored `outputs/` and preserve the recorded data; expect different timings on another machine or under different load.
